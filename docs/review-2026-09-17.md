## Changes to the work process

The ledger test previously required every issue to stay unchecked and at
least five continuation items to stay unfinished. These assertions prevent
valid burndown. Keep issue coverage, priority ordering, checkbox syntax, and
severity checks while allowing completion. Acceptance evidence and issue
closure remain review obligations; a Markdown syntax check cannot prove them.

The July “local/uncommitted” language describes work now present in `204fe36`.
Preserve July artifact hashes as dated evidence, record current host checks
separately, and update issue implementation notes when a reviewed PR merges.
Do not overwrite historical issue evidence or claim the baseline commit was
itself bot-reviewed.

Open one focused PR per step. Require CI success and completed bot review on
the current head, address outstanding findings, and merge only after both
are clean. Split large security issues without closing the parent issue until
all of its acceptance criteria pass. Engine changes need both Retro68 product
builds and applicable target tests; documentation and host tools need the
checks appropriate to their scope.
